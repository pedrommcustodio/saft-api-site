2. What this notice covers

This notice covers the SAF-T (PT) validator API and these website pages. It does not cover Zyla API Hub or RapidAPI. Those companies have their own notices, and a call made through them reaches them before it reaches us.

3. Roles

A business that uploads a SAF-T file is the controller of the personal data in that file. For the time it takes to answer the request, we act as that business’s processor. Regulation (EU) 2016/679 (GDPR) and Portuguese Law 58/2019 of 8 August apply. We do not decide why the file is processed. A data-processing agreement should be in place before a business customer relies on this API. This page is not that agreement.

4. Data we process

A SAF-T file can contain customer and supplier names, tax numbers, addresses, emails, phone numbers and purchase history, plus the company’s own identity. We also see technical data: request size, duration, the result counts, and a short hash of the header tax number. We do not create accounts.

5. How the file is handled

The file is processed in memory and discarded when the response is sent. It is not written to a database, not logged, and not sent to any other service by us. Uploads are kept in memory rather than in a temp upload file. Building an Excel file can create a short-lived temp file, which is deleted before the response is returned. We make no outbound call that carries file contents (no VIES lookup, no error service that stores the body).

6. Logs

Logs may contain a request id, the byte count, the duration, error and warning counts, and a short SHA-256 prefix of the header tax number. They do not contain the file name, the file body, customer names, or the raw tax number. Suggested retention for those logs: [LOG RETENTION, for example 30 days]. Confirm this matches the host you actually use.

7. Where processing happens

The planned host is an Oracle Cloud Infrastructure virtual machine in an EU region, preferably Frankfurt (eu-frankfurt-1) or Madrid (eu-madrid-1), subject to the tenancy home region. The marketplace gateway (Zyla and/or RapidAPI) sits in front of that host and can see the uploaded file in transit. Say so in the listing. Do not claim that nobody but you sees the file.

8. Legal bases

Where we are a processor, we process on the controller’s instructions in order to perform the API call (GDPR Article 28). Security logs, if we determine the purposes ourselves, rely on legitimate interests (Article 6(1)(f)): keeping the service reliable and detecting abuse, limited to the fields in section 6. Law 41/2004 (electronic communications privacy), as amended, matters only if cookies or similar storage are added later. These pages set no cookies.

9. Retention

File contents are not retained after the response. There is no history feature. We cannot recover a file that was uploaded earlier, and we cannot hand back a copy of it.

10. Rights

Data subjects can ask the controller (the business that holds the SAF-T) for access, rectification, erasure, restriction, portability and objection. They can also complain to the Comissão Nacional de Proteção de Dados (cnpd.pt). Requests sent to us about a file we no longer have will be answered with that fact. Contact [CONTACT EMAIL].

11. Security

The API refuses document-type declarations in uploads, caps file size, and can require a marketplace proxy secret so that the origin is not called directly. HTTPS is terminated at the reverse proxy.
